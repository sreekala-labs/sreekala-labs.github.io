topic: Idempotency Key
summary: "Summary of Idempotency Key"
---

Idempotency Key is a unique value generated by a client to tag an API request. It ensures that the request is only processed once 
in case of system failure or network timeout preventing duplicate charges.

Example: POST request is non-idempotent meaning that calling the same request twice leads to change in the state. 
If during payment, the system times out, then retrying the same request should prevent duplicate charges. In order to achieve this, we use idempotency 
key since the client does not know if the server-side succceeded. 

Client sends in a unique Idempotency Key as part of the header. The server checks "Have I seen this before?"

1. If not seen, processes the request, stores the result keyed by that ID.
2. If seen and processed, just returns the same response.
3. If seen but still in progress, returns a 409 or makes the client wait.

One thing that comes into mind is how long do you store the idempotency key for? 
Typical answer would be 24 hours by storing the key in Redis Cache with TTL. Too short is not good and leaving it there indefinitely costs storage.

**Client Side Implementation:**

```python
import requests 
import uuid 

def create_order(order_data):
    #Generate a UUID.
    idempotency_key= str(uuid.uuid4())

    #POST request with idempotency_key set in header.
    response = requests.post(
        "https://api.example.com/orders",
        json = order_data,
        headers={"idempotency_key": idempotency_key}
    )
    
    return response.json()

def create_order_with_retry(order_data, max_retries=3):
    idempotency_key= str(uuid.uuid4())
    
    for attempt in max_retries:
        try:
            response= requests.post(
                "https://api.example.com/orders",
                json= order_data,
                headers={"idempotency_key":idempotency_key},
                timeout=5 
            )

            return response.json()
        except requests.exceptions.Timeout:
            print(f"Attempt {attempt + 1} timed out, retrying with same key...")
            continue 
    
    raise Exception("Max Retries exceeded")    
```

**Server Side Implementation:**

```python
from flask import Flask, request, jsonify
import redis
import json 
import hashlib

import redis.cache

app=Flask(__name__)
#Create an instance of Redis
r= redis.Redis(host="localhost",port=6379, db=0)

#TTL for Idempotency Key
IDEMPOTENCY_TTL= 60 * 60 * 24 #24 HOURS.

#API method declaration.
@app.route("/orders", methods=["POST"])
def create_order():
    #Gets the idempotency_key from the header.
    idempotency_key = request.headers.get("idempotency_key")

    #If the key is not present, throw an error.
    if not idempotency_key:
        return jsonify({"error":"Idempotency-Key required"}),400

    #Define the redis key
    redis_key=f"idempotency:{idempotency_key}"

    #Check if it is existing
    existing = r.get(redis_key)
    
    if(existing):
        stored= json.loads(existing)
        if stored["status"]=="completed":
            return jsonify(stored["response"]), stored["status_code"]
        elif stored["status"]=="in_progress":
            return jsonify({"error": "Request already in progress"}), 409

    # This part is crucial to avoid race condition if two requests come in at the same time. This code ensure that the status is set before processing.
    r.set(redis_key,json.dumps({"status":"in_progress"}), ex=IDEMPOTENCY_TTL)
    
    order_data= request.get_json()
    order_id= "order_" + hashlib.md5(str(order_data).encode()).hexdigest()[:8]
    response_body = {"order_id":order_id,"status":"created"}
    
    r.set(redis_key,json.dumps({
        "status":"completed",
        "response":response_body,
        "status_code":201
    }),ex=IDEMPOTENCY_TTL)
    
    return jsonify(response_body), 201
```

**Note:**
In a real system you'd want this check-and-set to be atomic 
(e.g., Redis SETNX or a Lua script), not two separate calls, otherwise two concurrent requests could both read "not found" before either writes.
